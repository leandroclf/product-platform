# Specialized Dot Evolution

Keep specialist roles as Skills by default.

Promote a Skill to a specialized Dot only when: platform support exists; workload is recurring and materially independent; persistent context improves outcomes; access can be isolated; delegation/evidence remains bounded; measured quality or latency benefit exceeds coordination cost.

Do not promote merely to mirror an org chart. Tech Lead/Engineering Dot retains integration ownership unless experiments demonstrate a better topology.

Inter-dot work must carry objective, scope, permissions, evidence requirements and stop conditions. Avoid concurrent mutation of the same repository area without explicit reconciliation.
