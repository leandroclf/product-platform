# Dot Calibration and Feedback Loop

Start conservative. During onboarding, teach goals, quality bar, escalation preferences, approved projects and examples of acceptable completion.

Feedback becomes durable policy only when it is repeated/generalizable. One-off preferences stay task-local. Proposed durable changes are version-controlled here through OpenSpec.

Review calibration periodically using evidence: false completions, unnecessary approvals, missed approvals, stale-context incidents, retry/circuit events, rework rate, CI failures after agent changes and unnecessary specialist fan-out.

Do not encode secrets or transient mutable facts in Custom Rules.
